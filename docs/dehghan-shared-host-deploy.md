# استقرار مستقل دهقان روی هاست اشتراکی

هر دو کسب‌وکار از همین مخزن کد استفاده می‌کنند، اما دیتابیس، برنامهٔ Python، فایل `.env` و ریشهٔ انتشار فرانت‌اندشان جداست. داده‌های ناصری را به دیتابیس دهقان کپی نکنید. هر تغییر کد ابتدا آزموده و سپس به هر دو استقرار منتشر شود؛ انتشار در یکی، دیگری را خودکار به‌روزرسانی نمی‌کند.

## وضعیت و پیش‌نیاز

- ریشهٔ دامنهٔ دهقان در cPanel: `/home/getsmart/public_html/dehghanerp.getsmartspace.ir`
- برنامهٔ API پیشنهادی: `api-dehghanerp.getsmartspace.ir` با ریشهٔ Python مستقل، مانند `/home/getsmart/dehghanerp_backend`
- یک دیتابیس MariaDB **جدید و خالی** و کاربر اختصاصی دهقان با دسترسی فقط به همان دیتابیس
- SSL معتبر برای هر دو دامنهٔ دهقان، ظرفیت برنامهٔ Python و دیتابیس در پلن، و نسخهٔ Python سازگار
- پیش از ساختن کاربر یا رمز، نام دقیق دیتابیس و اپلیکیشن را با محدودیت‌های cPanel هماهنگ کنید؛ رمزها را در گفتگو یا مخزن نگذارید.

## فرانت‌اند

در `frontend` با `npm run build:dehghan` بستهٔ دهقان ساخته می‌شود. تنظیمات عمومی در `.env.dehghan` است: نام «سیستم مدیریتی مدیر دهقان» و API اختصاصی. خروجی `dist` را **فقط** در ریشهٔ دامنهٔ دهقان منتشر کنید، همراه `.htaccess` مخصوص SPA. فایل‌های ناصری را در این پوشه کپی نکنید.

ساخت ناصری با `npm run build` ادامه دارد. بعد از هر تغییر، هر دو خروجی را بسازید و هرکدام را در دامنهٔ خودش منتشر کنید.

## بک‌اند

برای دهقان یک کپی/checkout مستقل از همان نسخهٔ Git و یک Python App مستقل بسازید. در `.env` همان کپی، مقادیر زیر لازم است؛ این فقط الگوست و نباید با مقادیر واقعی در Git ثبت شود:

```dotenv
DEBUG=False
SECRET_KEY=<unique-secret>
ERP_DISPLAY_NAME=سیستم مدیریتی مدیر دهقان
ALLOWED_HOSTS=api-dehghanerp.getsmartspace.ir
CORS_ALLOWED_ORIGINS=https://dehghanerp.getsmartspace.ir
DB_ENGINE=mysql
DB_NAME=<dehghan-database>
DB_USER=<dehghan-database-user>
DB_PASSWORD=<unique-password>
DB_HOST=localhost
DB_PORT=3306
```

Passenger را به `naseri_erp.wsgi.application` همین checkout وصل کنید. پس از نصب requirements در محیط مجازی همان برنامه، `python manage.py check --deploy`، `python manage.py migrate` و `python manage.py collectstatic --noinput` را فقط در بک‌اند دهقان اجرا کنید؛ سپس برنامهٔ دهقان را restart کنید. در تمام این مراحل مسیر و متغیرهای محیطی را قبل از اجرای migration بررسی کنید تا به دیتابیس ناصری متصل نباشید.

## آزمون پیش از استفاده

1. HTTPS هر دو دامنهٔ دهقان و پاسخ API را تأیید کنید.
2. صفحهٔ ورود باید نام دهقان داشته باشد و درخواست‌های شبکه به `api-dehghanerp` بروند، نه API ناصری.
3. مدیر دهقان را **در دیتابیس دهقان** بسازید. ورود ناصری نباید در دهقان کار کند.
4. یک کالای آزمایشی، خرید، فروش و فاکتور دهقان را بررسی کنید. QR باید به دامنهٔ دهقان برود.
5. در پنل ناصری مطمئن شوید دادهٔ آزمایشی دهقان دیده نمی‌شود.

انتشار خودکار را تنها بعد از گذراندن این آزمون‌ها فعال کنید؛ در نسخهٔ اول، یک release مشترک و انتشار کنترل‌شده برای هر دو کسب‌وکار ساده‌تر و امن‌تر است.
